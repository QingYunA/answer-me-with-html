Redis vs Memcached

Which in-memory cache should you pick?

The short version

Memcached is a minimal, multi-threaded, volatile key→blob cache. Redis is an in-memory data structure server that can cache, persist, replicate, and do much more. Both deliver sub-millisecond reads. For most new projects, Redis is the safer default; Memcached wins in a narrow case of simple, huge, throughput-bound caching.

When to choose which

Choose Redis if you…

  • need more than plain get/set (counters, leaderboards, queues, sessions, rate limiting)
  • want the cache to survive restarts or fail over automatically
  • cache large or structured values and want partial updates
  • prefer one tool for cache, pub/sub, and light data work

Choose Memcached if you…

  • only need a simple, ephemeral, string/blob cache
  • want to saturate many cores with huge request volumes
  • cache small, uniform items and want minimal memory overhead
  • value operational simplicity and a permissive license

Recommendation

Default to Redis (or its open fork Valkey if licensing matters). It does everything Memcached does, is fast enough for nearly every workload, and gives you room to grow into persistence, HA, and richer data types. Pick Memcached only if your needs are strictly simple key/value caching at very high multi-core throughput, or you already run it successfully.

Whichever you use: set TTLs, plan for cache stampedes, and make sure your app tolerates a cold cache.
