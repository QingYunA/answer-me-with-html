TCP Connection Setup & Teardown

The three-way handshake and the four-way termination, step by step

Why this exists

TCP provides a reliable, ordered byte stream. Before data flows, both sides must agree that they are ready and must exchange their initial sequence numbers (ISNs), which are used to order and acknowledge bytes. When finished, each direction of the stream is closed independently, so that no in-flight data is lost.

Key header flags: SYN (synchronize sequence numbers), ACK (acknowledgment field is valid), FIN (sender has no more data), RST (abort).

Three-way handshake

  1. SYN — The client picks a random ISN x and sends a segment with SYN set. It enters SYN_SENT.
  2. SYN-ACK — The server picks its own ISN y, acknowledges x+1, and sets SYN as well. It enters SYN_RCVD.
  3. ACK — The client acknowledges y+1. Both sides are now ESTABLISHED; this segment may already carry data.
A SYN consumes one sequence number, which is why the acknowledgment is x+1 rather than x. Random ISNs help prevent old duplicate segments from being confused with a new connection, and make blind spoofing harder. SYN options such as MSS, window scale, SACK-permitted and timestamps are negotiated here too.

Four-way teardown

  1. FIN — The side that finishes sending first (active closer) sends FIN and enters FIN_WAIT_1.
  2. ACK — The peer acknowledges it and enters CLOSE_WAIT. The active closer moves to FIN_WAIT_2. The connection is now half-closed: the peer can still send data.
  3. FIN — When the peer's application is done, it sends its own FIN and enters LAST_ACK.
  4. ACK — The active closer acknowledges and enters TIME_WAIT; the peer goes to CLOSED on receiving it.

TIME_WAIT

The active closer waits for 2 × MSL (maximum segment lifetime; commonly 60 seconds total on Linux) before fully closing. This ensures the final ACK can be retransmitted if lost, and that stray delayed segments from the old connection expire before the same 4-tuple is reused.

Steps 2 and 3 are separate because the receiver of a FIN may still have data to send. If it has none, it can piggyback ACK and FIN in one segment, giving a three-segment close. If both sides send FIN simultaneously, both pass through CLOSING. An RST aborts the connection immediately without this exchange.
