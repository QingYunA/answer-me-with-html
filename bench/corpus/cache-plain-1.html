Redis vs Memcached

Choosing an in-memory cache for your application

The short version

Both are fast, in-memory key-value stores that sit in front of a slower database. Memcached is a deliberately minimal, multi-threaded cache for opaque blobs. Redis is a richer data-structure server that can cache, persist, replicate, and do much more. For most new projects Redis (or a compatible fork such as Valkey) is the safer default; Memcached still shines for simple, very large, multi-core cache fleets.

How they fit in

Both are most often used in the cache-aside pattern: check the cache, fall back to the database on a miss, then populate the cache with a TTL.

When each one wins

Choose Redis when you need…

  • Data structures: leaderboards, queues, counters, sessions, rate limiters
  • Cache that survives restarts (warm start) or replication for high availability
  • Pub/Sub, streams, distributed locks, or Lua-scripted atomic operations
  • Fine-grained eviction and TTL control
  • One tool for caching plus other workloads

Choose Memcached when you need…

  • A pure, simple cache of small-to-medium blobs (HTML fragments, query results)
  • Maximum throughput on a single many-core machine
  • Minimal operations and a very predictable memory model
  • Data that is cheap to lose and rebuild
  • An existing, proven Memcached fleet

Decision flow

Recommendation

Default to Redis (or the open-source Valkey fork). It covers everything Memcached does as a cache, adds persistence, replication, and rich data types, and its flexibility lets you grow into new use cases without adding another system. Most managed services (AWS ElastiCache, GCP Memorystore, Azure Cache) offer it.

Pick Memcached only if your needs are strictly simple key-to-blob caching, you want to squeeze the most throughput from multi-core nodes, and you value operational minimalism, or you already run it successfully.

Practical tips

  • Always set a TTL and plan for cache stampedes (jittered expiry, request coalescing).
  • Set maxmemory and an eviction policy (e.g. allkeys-lru) in Redis when using it purely as a cache.
  • Treat the cache as disposable: the database remains the source of truth.
  • Benchmark with your real payload sizes; the performance gap is rarely the deciding factor.
