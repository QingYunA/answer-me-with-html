## A component written as a ::: block is an error

A draft that writes a component the way VitePress, Docusaurus or Pandoc write an admonition, `:::callout` … `:::`, used to render the lines as plain text with no warning. Now `am lint` and `am render` report it with the right syntax, together with any other errors in the draft, and no page is written (#336):

```
✗ L2 [fence] write a component as a fenced code block, not :::callout
  Correct example:
    ```callout warn Caution
    Close the valve before you remove the pump.
    ```
```

- Only a known component name counts: `:::note`, a bare `:::`, and `:::` inside a code block stay text.
- `SKILL.md` now says above the component table that a component is a fenced code block.

## 把组件写成 ::: 块会报错

草稿如果按 VitePress、Docusaurus 或 Pandoc 提示框的写法写组件，比如 `:::callout` … `:::`，以前会被当成普通文字输出，也没有任何提示。现在 `am lint` 和 `am render` 会报错并给出正确写法，和草稿里的其他错误一起列出，不生成页面（#336）：

```
✗ L2 [fence] write a component as a fenced code block, not :::callout
  Correct example:
    ```callout warn Caution
    Close the valve before you remove the pump.
    ```
```

- 只有已知的组件名才报错：`:::note`、单独的 `:::`，以及代码块里的 `:::` 照旧是文字。
- `SKILL.md` 在组件表上方写明：组件要写成代码块。
